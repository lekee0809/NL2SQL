# V1 大版本路线（本机优先）

## 1. 可控的会话记忆（已开始）

- 已实现：会话 QuerySpec、当前轮数、首轮/最后一句问题和待确认候选值存入本机 SQLite；服务重启后可续问，浏览器重开后可从会话摘要列表选择恢复或删除。过期会话在启动和访问时清除；可配置 `SESSION_STORAGE=memory` 退回原模式。
- 边界：不保存查询结果、SQL、模型输出或 API Key；本机 SQLite 文件仍可能包含用户问题与商品/客户名，应放在仅本人可访问的目录并纳入备份/清理策略。
- 已实现：跨页面的会话轮次冲突检测，旧续问不覆盖新状态；会话列表只暴露摘要。
- 已实现：默认最多保存 1000 条会话，可配置；本机启动预检会验证存储是否可写。
- 待完成：多进程/并发压力验证。当前默认只保留闲置未超过一小时的会话，不是永久用户偏好记忆。

## 2. 多轮查询可靠性（下一阶段）

- 建立续问回归集：继承/替换/删除条件、实体 ID 不丢失、歧义澄清、过期恢复、重启恢复和并发更新。
- 对同一会话的并发续问引入版本号或冲突检测，避免后到请求覆盖先到请求。
- 将“本地规则已理解”和“需模型补全”的边界明确记录在评测报告中，优先减少错误继承，而不是只追求零 token。

## 3. 结果展示（第三阶段）

- 后端返回列的语义元数据（维度/指标、金额/数量/百分比/日期、单位），前端据此格式化，避免仅凭列名猜测。
- 按数据形态选择图表，并允许用户切回原始表格；空值、负值、超出返回上限等情况明确提示。
- 使用真实查询样本做桌面和窄屏验收，不仅依靠模拟数据测试。

## 4. 为 MCP 接入预留边界（上述稳定后）

将查询、会话与目录检索整理为可复用的服务接口，网页和将来的 MCP 适配层调用同一套权限、参数化 SQL 与只读校验逻辑。MCP 只是接入层，不绕开现有安全链路，也不直接读取会话 SQLite 文件。
